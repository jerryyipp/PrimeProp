================================================================================
MORE WAYS TO MAKE PRIMEPROP MORE ADVANCED AND ACCURATE
================================================================================

Below are additional directions beyond what is already implemented.
Each can be adopted incrementally.

--------------------------------------------------------------------------------
CURRENT STATE (AS OF LATEST CODE) — WHAT'S DONE
--------------------------------------------------------------------------------

  Ingest (ingest.py):
    - Odds API restricted to bookmakers: fanduel, draftkings, betmgm.
    - Main-line selection per player: tightest juice; alt-lines dropped.
    - One-way markets dropped (imbalance == 999.0).
    - FuzzyNameMatcher score_cutoff = 95.
    - aggregate_snapshot_by_best_odds: best over_odds and under_odds across
      books per (player, stat_type, threshold); over_provider/under_provider set.

  Projection (projection.py, stats.py):
    - ProjectionResult(mean, stdev, n, confidence); weighted/simple/exponential.
    - blend_short_long_result (regression-to-mean style blend).
    - ensemble_projection (weighted combo of methods).
    - Optional matchup adjustment (adjust_for_matchup) for PTS/REB/AST using
      opponent defensive metrics from matchup.py.
    - Winsorization (optional via WINSORIZE_PCT).
    - Configurable: PROJECTION_N_GAMES, PROJECTION_METHOD, MIN_GAMES_FOR_PROJECTION,
      PROJECTION_STRATEGY (single/blend/ensemble), ENSEMBLE_WEIGHTS.
    - Stats from nba_api with 24-hour cache; Points/Rebounds/Assists; PRA/Threes
      via ENABLE_EXTRA_MARKETS.

  Optimizer (optimizer.py):
    - True EV from Normal(mean, stdev) + American odds; P(Over) via CDF.
    - best_ev, recommended_side, recommended_odds, recommended_provider.
    - Optional calibration (calibration_params.json): p' = clamp(a*p + b, 0, 1).
    - rank_props_by_edge sorts by best_ev descending; ev_threshold filter.
    - Edge kept for display and fallback when odds missing.

  Database & automation:
    - grade_picks.py: auto-fetches actual results from NBA.com, updates won.
    - backtest.py: fits calibration from graded picks, saves to calibration_params.json.

--------------------------------------------------------------------------------
1. RICHER PROJECTIONS (ACCURACY)
--------------------------------------------------------------------------------

1.1 Home/away and rest context

  - Gap: Projections use only player history; no home/away or rest days.
  - Add: In main, resolve game context (home_team, away_team from Odds API).
    For each player, determine if home/away and days since last game.
  - Use: In projection or a wrapper: home/away multiplier (e.g. +2% home),
    rest-day adjustment (e.g. -1% on back-to-back). Reduces bias in extreme
    schedule spots.

1.2 Season-to-date vs last-N blend

  - Gap: All methods use last N games; no explicit season baseline.
  - Add: Optionally fetch season-to-date average; blend projection = alpha *
    last_N + (1 - alpha) * season_avg with configurable alpha. Helps when
    sample is small or noisy (e.g. return from injury).

1.3 Confidence interval in alerts

  - Today: Alerts show mean±stdev, best_ev, side, odds.
  - Add: Optional "projected 24.2 (20–28)" style 80% or 90% interval in
    alerts. Helps users judge risk vs line.

--------------------------------------------------------------------------------
2. BET SIZING AND ODDS (PRODUCT)
--------------------------------------------------------------------------------

2.1 Kelly or fractional stake suggestion

  - Idea: Given EV and odds, suggest stake size (e.g. half Kelly).
  - Add: In optimizer or a small bankroll.py: kelly_fraction(ev, odds) ->
    fraction of bankroll. Optional in alerts: "Suggested stake: 2% of
    bankroll (half Kelly)."
  - Use: Helps users size bets by expected value instead of flat units.

--------------------------------------------------------------------------------
3. CLOSING LINE VALUE AND LINE MOVEMENT (TRUST + ACCURACY)
--------------------------------------------------------------------------------

3.1 Closing line value (CLV)

  - Idea: Beating the closing line is a strong signal of value.
  - Add: Store closing_line (and optionally closing_odds) per pick, e.g.
    scraped or from API at game time. Compare our pick's line to closing.
  - Report: "We took Over at 24.5, closing was 25" = positive CLV. Add CLV
    to backtest output and any dashboard so users see how often they beat
    the close.

3.2 Line movement tracking

  - Idea: Track the same prop over time (e.g. line was 24.5 morning, now 25).
  - Add: Persist snapshots (snapshot_id, timestamp, lines) or (player, stat,
    line, timestamp) in DB or files. A small line movement module: for each
    prop, compare current line to earliest/previous line.
  - Use: In UI/alerts: "Line moved from 24.5 to 25 (we like Over)." Later:
    filter "only show props with line movement in our direction."

--------------------------------------------------------------------------------
4. INGEST ROBUSTNESS AND QUALITY
--------------------------------------------------------------------------------

4.1 Retries and circuit breakers

  - Gap: Failed provider requests are skipped; no retries.
  - Add: Retries with exponential backoff; timeouts per request; circuit
    breaker so one bad provider doesn't block snapshots. Log failures for
    debugging.

4.2 Snapshot persistence for replay

  - Idea: Store MarketSnapshot (or key fields) so you can replay and audit.
  - Add: Optional persistence of snapshots to DB or files (snapshot_id,
    timestamp, lines). Enables backtesting on historical lines and
    debugging edge cases.

--------------------------------------------------------------------------------
5. OPTIONAL ML AND ADVANCED FEATURES
--------------------------------------------------------------------------------

5.1 Simple ML projection model

  - Idea: Use features (last N stats, opponent defensive rating, home/away,
    rest, pace) to predict stat. Start with ridge or gradient boosting
    (sklearn, LightGBM) on historical (player, game, stat) data.
  - Add: src/ml_projector.py: train offline on game logs; at inference,
    take (player_id, stat_type, matchup_features) and return projected value.
    Plug in as ProjectionProvider; use in ensemble and "filter by AI pick."

5.2 PRA and Threes in Odds API

  - Gap: main.py may request only player_points, player_rebounds,
    player_assists. PRA and Threes are supported in projection/stats via
    ENABLE_EXTRA_MARKETS but must be in the Odds API markets param.
  - Add: If your Odds API tier supports them, add
    "player_points_rebounds_assists,player_threes" to markets. Quick way to
    expand props without structural changes.

--------------------------------------------------------------------------------
6. SUMMARY DIAGRAM (CONCEPTUAL)
--------------------------------------------------------------------------------

  Inputs: Odds API, NBA Stats, Matchup/Opponent
       |
       v
  Projection: Last N, Variance (mean/std), Matchup adjust, Blend, Ensemble
       |
       v
  Evaluation: P(Over) from CDF, True EV with odds, Calibration
       |
       v
  Output: Rank by best_ev, Alerts, Picks DB, Grade picks, Backtest
       |
       v
  Backtest feeds calibration; CLV and line movement are future enhancements.

--------------------------------------------------------------------------------
7. SUGGESTED PRIORITY (FOR IMPLEMENTATION)
--------------------------------------------------------------------------------

  - Quick wins: PRA and Threes in Odds API (5.2); confidence interval in
    alerts (1.3).
  - High impact: Home/away + rest (1.1); Kelly suggestion (2.1); retries and
    circuit breakers (4.1).
  - Trust and differentiation: CLV (3.1); line movement (3.2); snapshot
    persistence (4.2).
  - Advanced: Season blend (1.2); ML projection (5.1).
